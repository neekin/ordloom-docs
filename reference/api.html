API 与数据契约 ​

1.1.0 的 CMS 公开只读文章接口与会员 Session/CSRF API 由宿主显式挂载，路由、请求字段和边界见 CMS 与会员 API。这些接口不授予通用后台写入权限。

商城另提供公开商品目录、当前会员订单及后台库存调整，使用 Session/CSRF、UUID 幂等编号与服务器核价，见 商城 API。订单和库存不接受通用字段更新。

微信入口包括公众号 OAuth、小程序 code 交换、自己的绑定和平台签名回调；只有平台消息端点免 CSRF，身份写入沿用会员 Cookie/CSRF。见 微信 API。OpenID 与平台 session_key 不作为客户端会员凭据。

接口相对于插件挂载点。例如挂载到 /admin/ 时，下面的 /api/me/ 实际为 /admin/api/me/。

model_key 使用 app_label.model_name，例如 projects.project。下表管理接口保留 Django Session 与 CSRF 机制，外部只读数据服务的 Bearer 凭据不能替代管理会话。

1.1.0 API 与配置扩展 ​

1.1.0 新增 GET/POST /api/pages/<id>/versions/。GET 支持 offset 分页或 version 历史详情；POST 使用 publish、restore 或 rollback 操作，要求最新草稿修订、指纹及当前发布指针，协作工程还需配置令牌。角色与冲突规则见 页面版本 API。

原页面详情增加草稿修订、当前发布版本与未发布修改标识；公开分享、表单、取数和通知读取当前公开快照。公开入口不提供历史版本选择或发布能力。

图表增加可选 values、series，数据集绑定增加 interaction，报表引用增加 reportInteraction；后两项仅接受已有输出字段与已声明标量参数，见 联动契约。问卷章节、分步与类型化条件保存在原页面/题目配置，见 问卷协议。

原 GET /api/task-diagnostics/ 增加安全运行汇总和告警外发历史，权限仍限有效超级管理员；不新增网页执行能力。配置与观测边界见 运行指标。

JSON 响应 ​

成功：

json
{"ok": true, "data": {"id": 1}}

失败：

json
{"ok": false, "error": "校验失败", "errors": {"name": ["该名称已存在"]}}

部分错误还包含 context，例如验证码是否已经启用。除了检查 HTTP 状态，也应检查 ok。

登录与 CSRF ​

登录前读取配置，登录后读取账号信息，并按返回的 csrf_token、csrf_cookie_name 管理后续请求。登录会轮换 CSRF；不要把旧令牌永久缓存。

写入请求携带会话与 X-CSRFToken。已有前端客户端处理了 HttpOnly、会话 CSRF、自定义名称和会话切换取消，扩展组件优先复用该客户端。

主表保存 ​

以下结构对应第一个业务模块中的模型：

json
{
  "data": {
    "name": "客户门户升级",
    "status": "draft",
    "budget": "12000.50",
    "description": "模型目录与明细需求整理"
  }
}

新增不传 id；编辑时在外层提供原始 id。data 必须是对象，合法空表单使用 {"data": {}}。JSON 请求使用 application/json 或 +json；上传和原生 Action 表单继续使用相应表单格式。

金额、大整数主键和字符主键按原值传递，不转换为浮点数。字段内部的 JSON、布尔和空值由实际表单解析。

分页、筛选与标识 ​

列表常用参数为 q、page、page_size、order_by，单页上限 100。筛选通过 f_<key> 传递，但值必须来自接口元数据中的实际选项，不能直接假设 f_status=draft 就是该项目的筛选编码。

特殊主键优先使用详情查询形式：/api/detail/projects.project/?object_id=...。对查询值正确 URL 编码；旧的主键路径形式也继续兼容。

关联解析与导出可使用 ids_json，其内容是 JSON 数组，例如 ["crm/2026,a", "partner#1"]。空数组表示明确的空选择；损坏的 JSON 不会退回到导出全部记录。

JSON 精确文本来源、凭据意图、明细上下文请使用各组件章节的契约。自定义客户端不能只复制视觉控件而省略服务端权限检查。

1.0.1 公开票据与数据扩展 ​

POST /api/share/<uuid>/events/ 按现有分享密码、独立链接和数据授权领取一次性票据；WebSocket /ws/public-page-events/ 在首帧认证，只发送组件失效信号。模板预览/创建增加可选 jsonFields，报表 chart.type 支持 antv:* 与角色映射。详细请求、范围和默认开关见 1.0.1 指南。

1.0.2 故障恢复与调度契约 ​

已启用通知的公开分享 content.dataGrant 增加可选 eventRevision，票据请求可通过 revision 原样回传。它是不可解释的配置校验标识，不授予数据权限；原有客户端不传该字段仍可使用旧契约。当前分享入口、密码和授权验证后，配置变化返回 HTTP 409 与 context.code: PUBLIC_PAGE_CHANGED，新客户端重新获取分享内容后再申请票据。

公开取数和票据的临时故障返回安全 JSON 503 与 Retry-After: 2；共享额度耗尽返回 429 与等待提示。WebSocket 的 retry 指示重新取票，refresh 指示重新加载配置，revoked 指示清除旧结果并停止；消息不包含模型或业务字段。生命周期关闭 4000 可续票，配置关闭 4001 需重载，1013 可退避重试，真实撤权 4403 不自动恢复。

API 客户端会把 Retry-After 交给只读调度层，写请求不增加自动重试。三路并发、消费者取消、读取超时、公开映射隔离与刷新模式的详细规则见 稳定性指南。

子应用 SDK v1（1.1.0 起） ​

员工目录 GET /api/extensions/、公开静态目录 GET /api/extensions/public/、前端资源 GET /api/extensions/<app>/asset/、专用页数据 GET /api/extensions/<app>/pages/<page>/。菜单与服务端数据分别校验权限，公开目录仅含显式公开组件；无网页任务执行接口。详见 接入指南。

GET /api/extensions/directory/ 为重新鉴权的只读应用目录和行业配方，普通 staff 只看授权应用，超级管理员额外查看停用声明。安装参考信息为本地发行包介绍，不提供匿名安装状态或在线安装/命令执行。见生态开放。

P1 增强保留上述协议；GET /api/task-diagnostics/ 在原 alert_deliveries 中新增可选 admission，返回入队意图状态计数与最近 10 条安全元数据。权限仍限当前有效超级管理员，admitted 表示已进入队列，不能当作机器人发送成功。无 HTTP 补偿/任务执行入口；由宿主命令定时执行，见 P1 指南。
