1.0.2：公开通知恢复、组件取数调度与发布门禁 ​

Ordloom 1.0.2 完成三项 P1 稳定性增强。页面、数据集发布版本、分享密码与链接、资源管理权、模型与字段权限继续沿用现有机制。本版没有数据库模型变更；从 1.0.1 升级无需新增迁移，仍建议执行标准迁移和静态收集命令。

bash
pip install --upgrade ordloom==1.0.2
# 已使用可选数据层的工程
pip install --upgrade 'ordloom[graphql]==1.0.2'
python manage.py migrate
python manage.py collectstatic --noinput

公开通知怎样恢复 ​

默认开关保持关闭。已启用的公开大屏、H5 和轮播页会按故障性质处理：

情况页面行为
短暂数据库、共享缓存或通道故障停用当前通知连接，按退避间隔重新申请一次性票据，完整复核当前权限后恢复；通知不可用时，推送组件沿用定时兜底
票据过期、丢失或连接寿命结束领取新票据，不把它当成公开授权永久失效
保存的页面内容改变清除旧绑定并重新获取分享内容、字段映射及配置标识，再建立通知连接；断线期间的配置变化也会在续票时检查
公开授权撤销、确认者失权或账号停用清空已有结果并停止读数和重连
分享关闭、密码改变、链接轮换或到期旧访问状态不能自动恢复成新授权；仍需通过当前分享入口与凭据校验
标签页隐藏、切屏或离开页面取消该页订阅、排队和在途读取；返回可见页面后重新授权和加载

网络重连使用指数退避和抖动，读取接口及票据接口的 Retry-After 会传递给调度层。真实授权失效不会进入通用重试。无法确认权限时，不返回新的业务数据；临时读取故障仍可显示上次结果及其更新时间，重试耗尽后标记过期。

通知只包含固定类型和本页获准组件 ID，不发送模型名、字段目录或业务值。票据仍短期、一次性、绑定原始同源 Host、协议与访问端地址；密码、授权 token 和票据均不会进入 WebSocket URL。

HTTP 公开取数的页面查询、共享缓存计数及执行阶段异常统一返回 JSON 503 与 Retry-After: 2；达到既有限额时返回 429 与 Retry-After: 60。响应不含内部异常或连接信息。

一页多个组件怎样取数 ​

数据集与嵌入报表共用页面读取队列，报表看板沿用相同调度实现。

项目1.0.2 行为
并发同一个页面最多 3 路读取；排队中的相同查询也会合并
查询合并数据集、发布版本和参数相同的在途查询共享请求；公开响应额外按字段映射隔离
单组件取消移除一个消费者不影响其他消费者；最后一个消费者离开才中止共享请求
超时每次实际读取最多 15 秒；超时释放名额，即使旧执行器忽略取消，迟到结果也不会写入新绑定。宿主数据库的查询截止时间仍由数据库配置管理
临时读取重试仅只读请求，最多重试 2 次；超时、网络错误、408/425/429 与可重试服务错误采用有界退避
权限与结构错误401/403/404/409 和权限范围错误不自动重试，清除旧结果
轮询错峰首次轮询增加按组件确定的少量相位偏移；常规轮询继续遵守原间隔
公开额度浏览器为同页安排最多 100 次实际读取/滚动 60 秒，相邻读取至少间隔 600 毫秒；服务器原有 120 次/60 秒共享缓存预算不变
429/503尊重服务器等待时间；429 或带等待提示的故障会冷却同页队列，等待不占并发名额；隐藏后再返回也不会重置公开页预算

手动、定时、推送和自动模式保持各自规则。通知恢复不会把手动组件变成自动刷新；通知密集时，同一组件只保留一次待办读取。队列只保留在途任务，不增加跨用户的业务结果缓存；现有服务器结果缓存及每次权限复核继续生效。

组件数量或更新速度超过额度时，实际刷新会排队，不能保证每个组件都达到其名义间隔。优先合并相同发布版本和参数、减少不必要的不同映射，并按数据变化速度设置间隔。100 次是前端调度预算，不替代服务端鉴权或限速；多个浏览器窗口仍可能共享服务器身份并触发 429。

部署配置 ​

已配置公开通知的宿主无需新增设置。基础接入仍需要共享 Django cache、ASGI 和 Channels/Redis，并由可信代理正确保留公开 Host、协议和访问端地址。

python
ORDLOOM_EVENTS = {"enabled": True}
ORDLOOM_PUBLIC_EVENTS = {
    "enabled": True,
    "ticket_seconds": 60,
    "connection_seconds": 300,
    "heartbeat_seconds": 15,
}

Redis 连接与读取超时应显式配置。通道层内部存在阻塞读取，通道连接的读取超时应大于其阻塞窗口；缓存计数与业务缓存则应使用短而有限的超时。以下是配置形状示例，地址应替换为宿主私有服务：

python
CACHES = {
    "default": {
        "BACKEND": "django.core.cache.backends.redis.RedisCache",
        "LOCATION": "redis://127.0.0.1:6379/1",
        "KEY_PREFIX": "ordloom-production",
        "OPTIONS": {"socket_connect_timeout": 2, "socket_timeout": 2},
    }
}
CHANNEL_LAYERS = {
    "default": {
        "BACKEND": "channels_redis.core.RedisChannelLayer",
        "CONFIG": {
            "hosts": [{
                "address": "redis://127.0.0.1:6379/2",
                "socket_connect_timeout": 2,
                "socket_timeout": 10,
            }],
            "prefix": "ordloom-production",
        },
    }
}

这不会改变已有租户范围的来源：公开读取继续用授权确认者的当前账号、原始请求 Host/协议及现有 ModelAdmin/组织数据权限构造只读上下文，匿名请求不能通过自定义租户头扩大范围。

手动发布的质量门禁 ​

Release 仍只响应 workflow_dispatch，普通提交和 PR 不会触发 Actions。输入已经推送的 ordloom-v<版本> 标签后，流程依次验证：

  1. Python 3.9/Django 4.2 核心与 Python 3.12/Django 5.2/GraphQL 全量回归、邮箱/UUID 账号回归。
  2. 前端单元及实际 React/Ant Design DOM 生命周期回归。
  3. 独占 PostgreSQL 的权限/绑定/通知检查、Redis 跨进程票据/限速/告警检查，以及双实例 90 秒故障注入冒烟。
  4. 构建 wheel、sdist 和前端包；核对版本、发布说明、包与源码逐文件一致、Python 3.9 语法及离线静态文件哈希；反例检查确认错误版本、缺失/短时/过期证据及文件篡改都会被拒绝。
  5. wheel 和 sdist 分别在核心及 GraphQL 环境隔离安装，验证迁移升级、模型无漂移、静态收集、会话路由、预检和数据查询。
  6. 验证已提交的至少 30 分钟真实时间持续运行记录，且覆盖当前运行代码与验收工具哈希。
  7. 门禁全部通过后，发布原始候选产物到 GitHub 与 PyPI。发布凭据仅在最后的发布任务中使用，缺失时停止。

持续运行需要另行手动执行，90 秒冒烟不能替代它。验收运行器只创建并清理自己拥有的服务，不接受现有数据库、缓存或远端目标，也不会清空宿主缓存。

bash
python scripts/benchmark_resilience.py --seconds 1800 \
  --output docs/benchmarks/resilience-local-run.json

运行器拒绝覆盖已有证据，重复运行请更换文件名。提交通过的 JSON 后，在手动 Release 的 endurance 输入中指定该仓库 docs/benchmarks/ 下的路径；默认值为本版的正式记录。

运行依赖 Python 3.12、Django 5.2、GraphQL 扩展、Daphne、Channels Redis、psycopg、httpx、psutil、Node.js 22+、前端开发依赖，以及本地已有的 PostgreSQL 17/Redis 6 Docker 镜像。输出记录两个实例、24 个组件/访问端、20 个不同参数查询、混合策略、短断与恢复、续票、配置刷新、隐藏暂停、撤权、请求量、延迟、内存及连接回收。

本版双实例实测 1802 秒、5916 次读取，每个访问端最多 3 路、每页滚动 60 秒最多 100 次，成功读取 P95 均为 173 ms，各续票 27 次；短断结束后 0.294–1.347 秒重新就绪，撤权后结果、读取队列、计时器及连接均清理。原生轮播运行 1263 秒（前台 1144 秒）、80 次切屏，覆盖移动 H5、配置刷新、不同映射隔离与真实数据变化，未发现脚本错误。

上述为有界本地证据；目标大屏的 24 小时以上轮播、真实代理、设备、HTTPS、租户配置和目标数据量，仍应在实际宿主验收。正式结果与原生浏览器记录见 路线图 和 源码验收记录。
