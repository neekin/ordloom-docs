公开分享与只读数据授权 ​

单页与轮播都通过分享设置控制公开入口。UUID、密码和链接令牌控制入口；业务数据还需要独立、按页的只读授权。

分享管理（页面与轮播） ​

升级后执行 python manage.py migrate，加载 0008_share_controls（VisualPage 与 ScreenPlaylist 新增 share_enabled、share_password、share_expires_at 字段，默认保持既有公开行为）。

  • GET/PUT /api/pages/<id>/share/、GET/PUT /api/screen-playlists/<id>/share/：读取或更新分享设置， 仅创建人或超级管理员可访问。PUT 支持部分字段：enabled（布尔）、password（4–64 字符，null 或空串清除； 服务端仅保存哈希）、expires_at（ISO 时间，需晚于当前且最长 10 年，null 恢复永久）。
  • 公开端 GET /api/share/<uuid>/ 与 GET /api/screen-playlists/share/<uuid>/ 依次校验开关、有效期与密码： 关闭分享返回 404「分享已关闭或不存在」，过期返回 404「分享链接已过期」；设置了密码时， 无密码参数返回 {"locked": true}（前端展示密码输入），密码错误返回 403 且不返回任何页面内容， 密码正确才返回内容。新界面使用请求头 X-Ordloom-Share-Password（encodeURIComponent 编码后发送）或提交请求体传输密码， 仍支持 ?password= 调用；不要在发送给接收方的链接中拼接密码。密码尝试限速默认开启，额度与错误响应见 分享密码限速。

独立分享令牌与访问记录 ​

执行迁移后，原有 UUID 链接与 share/ 的三字段响应保持兼容。分享面板可主动「启用独立链接」，随后可「轮换分享链接」。 启用/轮换产生新凭据，旧链接立即停止后续内容读取、公开授权取数与表单提交；不改变 UUID、访问密码、有效期、分享开关或数据授权。 保护启用后不能降级回无令牌的 UUID 访问，可通过关闭分享停止访问。已下载或当前浏览器已加载的内容无法远程撤回。

  • GET /api/pages/<id>/share-link/，轮播对应 /api/screen-playlists/<id>/share-link/，返回 protected/revision/generation/key。 POST 同一端点并提交 {"revision":当前修订号} 启用或轮换；冲突返回 409，令牌与无秘密操作审计同事务保存。 仅创建人/超级管理员能读取或轮换，未拥有的目标返回 404。原 share/ 设置接口不返回此凭据。
  • 新链接为 /s/<uuid>/#share_key=<key> 或 /s/playlist/<uuid>/#share_key=<key>；片段不进入 HTTP URL/Referrer 的查询部分， 客户端通过 X-Ordloom-Share-Key 请求头发送。二维码和复制均使用完整链接。服务端不接受该令牌的 query 参数。 凭据由私有 nonce、目标类型、UUID 与站点 SECRET_KEY 派生；更换站点密钥后需重新复制保护链接。
  • 轮播保存时按当前操作者权限记录每张子页面的令牌代次。公开轮播只提供匹配代次的子页面凭据，仍检查各页面的开关、到期和密码。 子页面首次启用或再次轮换后，旧轮播选页失效，有管理权限的账号需重新保存轮播；知道旧轮播链接无法取得新子页面令牌。 轮播与子页面可分别设置密码，播放器会尝试输入的轮播密码；密码不同的子页面会显示错误并跳过，不绕过独立保护。 后台「保存并播放」通过已有管理接口获取配置及当前账号有权管理的页面，关闭公开分享不影响后台授权播放，且不计公开访问。

访问采集默认关闭，按需在宿主设置中启用：

python
ORDLOOM_SHARE_ANALYTICS = {
    'enabled': True,
    'retention_days': 30,        # 1–365，查询窗口最多 90 天且不超过留存周期
    'daily_budget': 10000,      # 每个入口每天记录请求的近似预算，1–1000000
    'per_ip_per_minute': 120,   # 每入口/直接连接来源每分钟预算，1–10000
}

公开查看器每次进入生成临时 UUID，通过 X-Ordloom-Visit-ID 发送；仅内容入口请求采集，无此头的旧调用不记录。 密码提示、重试与成功合并为一次打开，首次成功标记不会被后续拒绝覆盖。轮播只统计轮播入口；切屏、预取、组件轮询和表单提交不增加浏览量。 这是可被客户端影响、受预算和缓存可用性约束的近似 PV/打开/拒绝/密码提示统计，不统计独立访客，也不作为不可篡改安全审计或认证限速。 多实例需共享 Redis 等原子 cache；缓存或数据库采集故障不阻断公开内容。来源使用 REMOTE_ADDR，不信任任意转发头。

分享面板「访问记录与统计」对应 GET /api/pages/<id>/visits/?days=7&page=1（轮播同前缀），每页 20 条。 仅当前创建人或超级管理员查看；关闭采集后仍可读取留存中的记录。仅保存时间、结果计数、IPv4 /24 或 IPv6 /64 网段和有限浏览器/系统类别； 不保存完整 IP、原始 UA、来源网址、链接令牌、访问密码、问卷答案或业务结果。按目标 UUID 保存，删除页面不级联删除访问记录，但其管理接口不再可读。

留存不依赖 HTTP 请求自动清理，由运维调度命令执行；默认预览、不触及业务记录或分享配置，支持 --database：

bash
python manage.py ordloom_prune_share_visits --json
python manage.py ordloom_prune_share_visits --apply --limit 10000 --json
python manage.py ordloom_check --json  # 同时诊断分享统计设置

每批最多 500 条，单次默认上限 10000、最大 100000；仅清理创建时间早于留存周期的记录，未来增加关联关系时拒绝级联清理。 隔离示例加 --share-analytics 可演示，使用临时 SQLite，不修改宿主数据库。

公开数据授权（页面专用只读） ​

升级后执行 python manage.py migrate，加载 0010_page_grant。页面创建人可在分享面板为该页面的 绑定组件开启公开数据授权，公开访客凭分享内容中的 token 读取绑定组件的数据；页面 UUID 本身 不授予任何业务数据权限。

  • GET/PUT /api/pages/<id>/grants/：读取或更新授权（仅创建人或超级管理员）。datasets 为 最多 20 个 {"datasetId","version"} 的列表，且必须是页面已绑定的发布版本；revoked 为布尔。 token 仅创建时生成并随 GET /api/share/<uuid>/ 的 content.dataGrant 下发，管理接口不返回。
  • POST /api/share/<uuid>/data/：公开执行绑定查询。请求须携带分享载荷中的 token 与与页面绑定 完全一致的 datasetId/version/params/mapping；执行以最近确认有效授权的账号当前权限运行真实权限栈， 响应只保留映射引用的输出字段；客户端参数与绑定不一致直接拒绝。分享关闭、过期、密码缺失或 授权撤销时返回错误，不返回任何业务数据。
  • 每次读取都重新检查授权执行账号当前模型、对象、字段权限和结构，包括缓存命中路径。 确认者变化时重置执行账号并轮换数据令牌；修改他人确认的授权页面会先撤销数据授权，再由当前账号明确确认。 仅原生 QuerySet/Manager、无软删除和对象/动态字段规则的模型级读权限允许缓存结果 60 秒；其余策略实时执行。 缓存 key 含 token、版本、参数、映射与授权更新时间；撤销立即失效。公开端另有每分钟 120 次的基础限流。 执行请求使用创建者身份及完整的独立 HttpRequest，不传递匿名访问者的租户头、筛选参数或 Session。
  • 授权变更审计（0012 迁移）：分享面板的「授权变更记录」显示创建、范围调整、撤销、恢复、 已授权绑定变更及删除页面。GET /api/grant-audits/ 提供只读分页（page、page_size 1–100）， 可按 page_uuid、action 筛选；普通 staff 只能读取自己创建页面的记录，超级管理员可读取全部。 授权操作及其审计记录在同一事务内保存，重复提交相同状态不产生新记录；页面删除后记录保留， 用户删除仅清空关联，保留操作人名称快照。记录不允许通过模型普通保存、更新、删除或批量覆盖修改。 只记录版本、映射字段和参数名，参数变化通过带密钥的摘要识别；不存 token、参数值、密码或业务结果。 审计仅覆盖启用此迁移后的管理 API 操作，不回填历史、不记录每次匿名访问，不能替代数据库级审计。

分享密码限速 ​

分享入口复用分享开关、有效期、令牌、资源权限及表单 CSRF 规则；多入口共用密码失败预算。

python
# 以下均为默认值；enabled=False 可沿用原密码校验行为。
ORDLOOM_SHARE_LIMITS = {
    'enabled': True,
    'window_seconds': 300,
    'max_failures': 10,
    'per_ip_failures': 100,
}

页面/轮播入口、公开数据读取和表单提交复用同一密码守卫及默认 Django 缓存。 固定时间窗口内，同一来源对同一页面或轮播最多 10 次失败、跨资源最多 100 次失败。 校验前预留额度以限制同时进行的密码哈希，成功后释放本次预留，不抹掉已有失败；持续正确的取数轮询不累计失败。 在途校验也占用额度，达到上限时即使密码正确仍需等待；无密码的入口提示不计数，受保护 POST 的缺失密码视为错误尝试。

错误密码仍返回 403；超过额度返回 429、Retry-After 秒数及 context.retry_after。 前端保留解锁表单，窗口结束后可使用同一密码重试。缓存异常或限速配置无效时，受密码保护的访问返回通用 503；无密码页面不依赖这项缓存。 修改配置请先运行 ordloom_check；时间范围 1–86400 秒，资源失败额度 1–10000，来源额度 1–100000，均为整数。

多 Web/命令进程须将 Django CACHES['default'] 指向同一具备原子 add/incr/decr 的 Redis 或 Memcached，不能以各进程的 LocMemCache 代替全局额度。 计数键使用 HMAC，不包含密码、原始 IP 或公开 UUID。来源仅取可信 REMOTE_ADDR，不会直接信任客户端的 X-Forwarded-For；代理部署需在可信边界正确设置来源。 同一 NAT 出口共享来源额度；未知来源归到同一预算。固定窗口、缓存逐出和共享出口的边界需按目标部署核对。
