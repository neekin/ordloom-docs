ordloom-payments 支付管理 ​

ordloom-payments 0.1.0 是商城交易闭环的独立子应用：订单支付交易、人工确认或宿主适配器确认、退款补偿与对账任务。要求 Python 3.9+、Django 4.2+、ordloom>=1.1.0,<2 与 ordloom-shop>=0.1.0,<0.2（单商户、CNY）。Ordloom 1.2.1 的应用目录包含其接入信息。

安装与接入 ​

bash
python -m pip install ordloom==1.2.1 ordloom-shop==0.1.0 ordloom-payments==0.1.0

注册 ordloom_payments.apps.ExtensionConfig，显式挂载 include("ordloom_payments.urls") 并执行 migrate。ORDLOOM_PAYMENTS={"enabled":True} 默认关闭。会员从 /payments/api/v1/payments/（POST order+request_key）为本人待支付订单创建交易；重放同一 request_key 返回原交易，金额始终以商城服务端核价为准。

渠道与语义 ​

  • 人工确认模式（默认）：不配置 provider 时，具备 confirm_payment 权限的管理员在后台动作「确认支付/标记失败」，退款通过 request_refund 权限后台确认。适合线下转账、对公入账等人工渠道。
  • 适配器模式：ORDLOOM_PAYMENTS["provider"]="myproject.payments.Adapter" 声明实现 create_payment(transaction)、verify_callback(request)、query_status(transaction)、refund(refund) 的适配器；回调端点 /payments/callback/ 仅在配置适配器后开放，验签由适配器负责，事件唯一键在数据库层面防重放。同一订单同时只有一笔进行中支付。
  • 订单衔接：支付完成不直写订单状态——对账任务 ext:payments.reconcile 由宿主调度，复核当前权限后复用商城 services.transition(...,'confirm') 确认订单；退款补偿同样按任务推进。库存归还仍由商城取消/超时路径唯一保证。
  • 管理沿用 Django 模型/对象权限与 ModelAdmin.get_queryset 范围；provider_ref 仅对 staff 序列化。

边界 ​

单商户/CNY、无多币种、无分账/发票/对账文件导出；verify_callback 的安全实现与真实支付平台联调、资金对账、纠纷处理属于启用前验收；适配器代码为可信宿主代码，不存在在线渠道配置或沙箱。完整指南见 https://neekin.github.io/ordloom-docs/guides/payments.html 。
