常见问题 ​

看不到业务模型 ​

确认模型已注册到 Django Admin，业务应用已加入 INSTALLED_APPS，当前账号拥有对应模块和模型权限。再检查 get_queryset() 或自定义菜单是否缩小了范围。

只有新增权限时看到录入页属于预期行为，不会同时开放列表与详情。

页面仍显示历史品牌 ​

确认安装的是 ordloom==1.0.0，并检查部署后的包版本及静态文件。项目自己的站点标题通过 ORDLOOM_SITE_TITLE 配置，见 环境与接入。

源码版本更新后，重建前端、同步包内静态资源，再重新部署与收集静态文件。不要只修改浏览器标题却遗漏登录页、页脚或演示资源。

写入返回 403 或 CSRF 错误 ​

检查当前会话、账号资格、对象权限以及最新的 CSRF 信息。登录会轮换令牌；HttpOnly 或会话 CSRF 不能只通过 document.cookie 读取。内置客户端会处理这些情况。

编辑器内容没有保存 ​

自定义包装控件应转发 value/onChange/id。确认没有把注册逻辑放入重复执行的轻量入口。保存失败时还需查看具体字段、明细或跨字段校验，而不是只检查编辑器是否有文字。

上传按钮不可用或上传失败 ​

独立前端演示没有连接 Django 时，上传入口不可用。真实项目还会检查字段格式、大小、图片实际内容、对象和 inline 权限、动态只读规则以及 storage 返回的地址。

若上传成功但图片不能显示，检查媒体服务、地址编码、签名链接有效期及跨域访问。上传后再次保存不应手工把 URL 编码成另一层存储名。

JSON 大整数变化 ​

使用接口提供的精确文本来源，不要先转为 JavaScript Number。格式化与压缩应只改变空白。具体说明见JSON 编辑器。

Markdown 预览一直加载或报 Worker 错误 ​

先检查原文是否仍可编辑，再检查构建产物、Worker 地址、MIME、CSP、CORS 和网络错误；预览失败可重试。跨域静态部署尤其需要核对 Worker 加载策略。

没有进入原生 Admin 编辑页 ​

默认完全接管挂载点下管理页面。需要原生兜底时使用 ORDLOOM_FULL_TAKEOVER = False，或将两套入口挂在不同路径。

地图空白 ​

先判断坐标控件是否正常。默认底图依赖外部瓦片服务；不可达时可以继续填写经纬度，或配置自己的 tile_url。当前没有 POI 搜索功能。

文档和安装后的界面不完全相同 ​

确认查看的是当前发行版能力还是设计概念图。遇到问题可在文档仓库提供包版本、Django/Python 版本、复现步骤与已脱敏的错误信息。
