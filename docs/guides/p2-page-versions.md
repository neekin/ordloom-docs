# 页面草稿、发布历史与回滚（1.1.0 起）

此功能从 Ordloom 1.1.0 提供。升级后先执行 `python manage.py migrate`，0028 新增页面修订、当前发布版本指针及不可变页面版本表。该功能无需 GraphQL；有数据绑定的页面继续按原配置启用可选数据层。

## 编辑与发布

1. 打开数字大屏或 H5 编辑器，进入「版本与发布」。
2. 旧页面与新建页面默认保留即时分享行为：首次发布前，保存仍更新公开链接。
3. 点击「发布首个版本并分离草稿」后，公开链接和轮播读取该发布快照。此后「保存页面」仅保存草稿，不改变公开内容；预览继续展示当前草稿。
4. 保存并检查草稿后，发布新的不可变版本；重复发布相同的最近版本不会新增重复历史。
5. 历史列表每页 20 条，可查看历史配置及与当前草稿的组件新增、移除、修改、顺序、名称和画布差异。
6. 「恢复到草稿」仅替换编辑草稿，待再次发布才影响公开链接。「回滚公开版」直接切换到指定历史版本，保留当前草稿。

发布和回滚复用当前资源管理权限；编辑权限可恢复草稿，当前读取权限可查看历史。协作撤销、工作区角色、所有权交接和超级管理员范围继续即时生效。操作要求最新草稿修订、配置指纹和当前公开版本；协作工程同时沿用配置令牌，过期操作返回 409。

## 快照与权限边界

快照只记录页面名称、种类及画布/组件配置。数据集绑定继续固定引用原数据集发布版本；数据行和授权凭据不会复制到页面版本。报表组件引用报表的当前定义，不承诺冻结报表定义，公开页面仍不执行私有报表。

公开分享、表单提交、公开取数和通知票据统一读取当前发布快照；发布前仍使用最近保存配置。分享密码、关闭/有效期、独立链接代次、公开数据授权及确认账号当前字段/对象/租户权限始终实时校验。回滚不会恢复已撤销的数据授权，也不会恢复旧密码、旧令牌或旧协作权限；历史版本所需字段/数据集已不可访问时，恢复和回滚明确拒绝。另一位非超级管理员管理者发布时，原确认账号的公开取数授权先撤销，需要在分享窗口重新确认。

修改已分离的草稿不会改变公开通知配置标识；发布或回滚更新后，现有通知连接发现配置变化并重新读取公开元数据。表单使用当前公开版本的题目和流程，已提交答卷仍保留自己的历史规则快照，后续发布或回滚不改写答卷。

公开授权窗口只列出当前公开配置实际绑定的数据集；草稿新增的绑定须先发布，随后显式确认公开授权。当前草稿及当前公开版本使用的绑定均保留在使用关系索引中。非当前历史版本的引用可在版本配置中查看，不会被当作正在播放的依赖。

轮播采用固定策略「跟随当前公开版本」，未开始页面版本管理时跟随最近保存配置。现阶段不开放通过 URL 指定任意历史页面版本，避免绕过当前发布决策；回滚后轮播下次加载该屏时读取回滚版本。已经打开的无数据通知静态页面需重新加载才能获取更新，行为与原公开分享一致。

## API

- `GET /api/pages/{id}/` 返回编辑草稿及 `draft_revision`、`draft_fingerprint`、`published_version`、`publication_mode` 和 `unpublished_changes`。
- `GET /api/pages/{id}/versions/?offset=0` 返回历史摘要、总数及当前草稿/发布状态。
- `GET /api/pages/{id}/versions/?version=1` 返回指定历史配置及与当前草稿的差异。
- `POST /api/pages/{id}/versions/` 支持 `action=publish|restore|rollback`；后两项还需 `version`。

操作请求必须从最新读取结果填入 `base_revision`、`base_fingerprint`、`base_published_version`（首次发布为 null），协作工程还需 `base_configuration_token`。管理 Session 与 CSRF 保持原规则；公开入口不提供发布、历史或恢复能力。

应用层拒绝修改/删除已存在的版本和覆盖式批量写入。删除页面仍清理该页历史，不阻断原页面删除功能；版本记录不是独立备份或跨页面恢复工具。
