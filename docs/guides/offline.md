# PWA、离线画布与业务快照

离线程序、画布编辑与只读业务快照分别配置。业务快照采用导出副本语义，需要由使用者主动保存。

## PWA 与诊断命令

数据层、事件和表单的双进程并发验证见仓库的 [容量验证方法与基线](https://github.com/neekin/simpleui-antd/blob/main/docs/capacity.md)。
包含 PostgreSQL/SQLite、真实 Redis、权限撤销、推送、限流及数值精度探针；需要单独的验证依赖和 Docker，
只创建自己的临时资源，不连接宿主已有数据库。结果不是生产容量承诺。

消息中心与审计留存的配置也纳入诊断；完整说明见下文。

- `GET /api/manifest.webmanifest/`：动态 PWA 安装清单，`name`/`short_name` 取自站点标题，`start_url`/`scope`
  为当前挂载点，图标指向包内 `static/ordloom/icons/`。工作台入口页自动注入
  `<link rel="manifest">` 与 `theme-color`；公开分享页不注入。离线画布单独启用，见下文。
- `python manage.py ordloom_check [--json]`：配置诊断，覆盖应用注册、URL 挂载、
  迁移状态（未应用时提示执行 `migrate`）、前端构建产物、可选 GraphQL 依赖（启用但不可用时判定失败）、
  站点配置与可视化数据概况；`--json` 输出机器可读结果，存在失败项时退出码为 1，可直接用于部署脚本。

### 离线画布与联网另存

默认关闭。执行迁移及 `collectstatic` 后，在宿主配置：

```python
ORDLOOM_PWA = {'offline': True}
```

使用 HTTPS 或 localhost，并从同源地址提供静态资源。在「页面搭建 → 本机画布与离线准备」点击
「准备或更新离线资源」，等待成功后打开「本机画布」。断网时可继续从 `<挂载点>/offline/` 打开，
也可在管理页面导航网络失败后进入通用画布；新建模板、导入 JSON、编辑排版、预览、保存本机修订及导出均可使用。
外链图片、音视频和外部链接不在离线预览中加载，包内六张图片及支持的图片 data URI 可使用。

本机文档保存在此浏览器的 IndexedDB，按域名和挂载点隔离，**不随登录账号隔离**；界面明确提示其类似本机 JSON 文件。
不会自动下载私有页面或业务结果。每挂载点最多 20 份文档，每份 2 MiB、合计 20 MiB；多窗口写入校验修订号，
冲突不覆盖较新内容，当前修改可导出。浏览器可能回收本机存储，重要文档需自行导出备份。

联网后登录 staff 账号，在上述面板显式选择文档修订「另存为新页面」。`POST /api/offline/import/` 使用当前
Session/CSRF 和账号权限，创建本人新页面，默认关闭公开分享；不覆盖已有页面。相同账号、文档编号与修订重试返回原页面，
不会重放内容覆盖后续在线编辑；原目标已删除或不再属于本人时返回冲突，另一个账号可显式另存自己的副本。
本机导入和联网另存均清除数据集/报表业务引用及页面数据授权，表单停止收集；联网后需重新绑定发布版本、字段与实参。

程序使用 `<挂载点>/ordloom-offline-worker.js`。同一精确 scope 已有其他 Service Worker 时拒绝准备，
可使用独立挂载点；更上层的宿主 PWA 可以保留。准备仅缓存清单内的包内静态资源及不含账号信息的通用画布入口，
逐项检查 SHA-256 和字节数，失败时保留旧缓存；不缓存管理 HTML、API、数据集查询结果、答卷、上传文件或凭据。
基础画布提供离线页面设计；只读业务导出需额外启用下节快照功能，仍不提供离线授权查询、表单提交队列或自动同步。程序更新遵循默认 Worker 生命周期，
提示更新已准备时关闭本站所有窗口并重新打开；关闭配置后 Worker 下次成功更新只清理自身缓存并注销，不删除本机文档。

### 离线业务快照

在已启用 GraphQL 数据层和离线画布的宿主上，可额外启用只读快照，默认关闭：

```python
ORDLOOM_PWA = {'offline': True, 'snapshots': True}
```

无需新增模型或迁移。执行前端构建/`collectstatic`，使用同源静态资源与 HTTPS/localhost。
页面列表每张大屏/H5 的「业务快照」先显示当前保存页面及可见数据组件数量；
用户确认保存到设备后，准备程序资源，再读取业务数据并保存独立本机副本。
若已有程序更新仍在等待激活，先关闭本站窗口并重新打开，再生成快照，避免旧离线程序无法展示新格式。

- `GET api/offline/snapshots/<page_id>/` 仅读取页面名称、类型、可见数据组件数及当前配置令牌，不执行业务查询。
  `POST` 提交 `{"configuration_token":"<读取到的令牌>","acknowledged":true}`；仅接受已有保存页面，
  不接受调用者上传查询或页面定义，复用 Session/CSRF、当前页面/数据集/报表的 read 权限与完整业务数据权限。
  默认仍按创建人隔离；显式协作的只读使用者也只能导出自己当前有权读取的数据，不借用页面创建人或公开授权身份。
- 只处理未隐藏、已绑定的组件：固定数据集发布版本按页面已保存实参执行，报表按生成时最新保存定义和实参执行。
  同一数据集版本/实参、同一报表/实参在单次生成中合并查询，整页共用原有 20 次查询预算。
  原有归档数据集的已保存引用可继续执行；权限/字段/类型失效、超限或任一组件失败时，整个生成失败，不保存半份快照。
- 响应保留布局、采集时间、每个数据组件的映射与映射所需输出值；不包含查询定义、业务实参、
  可继续执行的数据集/报表 ID、公开数据授权令牌或未映射输出列。表单停止收集，外链媒体不自动下载。
  明细/统计沿用组件配置的第 1 页或分组上限，不遍历全部业务记录；仍有后续结果时展示截断提示。
  字符串形式的 BigInt/Decimal 保持精度；图表沿用现有安全数值检查及数据库精度限制。
- 页面或引用报表配置在采集过程中变化会拒绝生成；业务查询在一段时间内依次执行，
  **不承诺跨模型、跨数据库同一时刻的一致性快照**。重新采集创建新副本，不改写旧快照。
- 每份最多 2 MiB、本机最多 20 份/合计 20 MiB，快照与可编辑画布使用独立 IndexedDB 库，均按源站及挂载点隔离。
  本机画布中的「只读业务快照」可查看、全屏、导入/导出 `.snapshot.json`、按修订号删除。
  数值、表格及 ECharts/AntV 数据复用现有渲染；报表转换为只读图表或表格，不再发起业务 API、轮询或订阅，表单不提交。
- **本机副本采用导出文件的访问语义**：当前浏览器使用者可查看/导出，不随在线账号隔离；
  断网后无法复核账号权限，也无法撤回已导出数据。生成前界面明确说明并由用户确认，按设备资料管理要求保留或删除。
  关闭宿主功能、退出或撤销在线权限不会删除已有本机副本及用户导出的文件。
  导入文件由使用者提供、可被编辑，不是服务器签名或审计证据，也不授予任何在线业务权限。
- 业务值只在用户主动保存的快照库/文件中，不进入 Service Worker 的程序资源缓存；
  管理 HTML、API、在线页面、表单答案和自动后台同步的原有边界不变。服务器不保存快照结果，不修改在线页面。

开发验证（临时 SQLite/专用临时 PostgreSQL，不连接已有宿主数据库）：

```bash
python scripts/test_backend.py ordloom.tests.test_offline_snapshots
python scripts/test_offline_snapshots.py
# 可选 PostgreSQL 依赖和归属校验见脚本头部
python scripts/test_ownership_postgres.py --snapshots
# frontend：文档、Worker、IndexedDB 模拟事务、快照映射
npm run test:offline-unit
# frontend：快照确认/冲突/程序更新、只读渲染（模拟 API，无 Canvas）
npm run test:collaboration-ui
```
