# P2：任务告警外发与运行指标（1.1.0 起）

Ordloom 1.1.0 提供任务告警外发与运行指标。任务外发默认关闭；运行指标默认关闭，复用宿主共享缓存与现有超级管理员诊断权限。升级需要执行迁移与静态收集；0029 为原 Webhook 端点增加用途标识，0030 保存外发入队意图，原记录默认保留模型事件用途。

## 开启机器人任务告警

先在现有 `ORDLOOM_WEBHOOKS.bot_targets` 中配置批准的钉钉/飞书机器人，签名密钥和私人地址仅保留于服务器设置，配置方式见 [机器人指南](bot-targets.md)。任务告警只接受 `bot:<标识>`，不接受任意 URL。然后设置：

```python
ORDLOOM_TASK_DIAGNOSTICS = {"enabled": True}
ORDLOOM_TASK_ALERTS = {
    "enabled": True,
    "cooldown_seconds": 3600,
    "external_owner": "1",  # 当前有效超级管理员的账号主键，也支持 UUID 字符串
    "external_targets": ["bot:operations"],
}
ORDLOOM_RUNTIME_METRICS = {"enabled": True}
```

`operations` 必须已存在于启用的 Webhook 目标配置中；负责人不能是普通 staff。最多 10 个不重复目标。站内通知仍需开启，原任务失败、超时、未观测与积压的判定、首次宽限和冷却继续适用。默认数据库必须同时承载告警状态、站内消息、账号和 Webhook 队列。

宿主按原方式调度命令：

```bash
# 先预览，不产生消息或外发任务
python manage.py ordloom_check_tasks --json
# 保存状态、站内消息和外发意图，再补偿到期意图入队
python manage.py ordloom_check_tasks --apply --external-limit 100 --json
# 独立投递；网络故障不阻塞告警评估和站内消息
python manage.py ordloom_deliver_webhooks --apply --json
```

外发与站内告警共用事件修订、冷却和恢复判定；重复评估不重复排队。事务队列沿用原租约、共享机器人发送间隔、平台签名、成功码校验和有界退避。每次发送前重新读取批准目标、凭据指纹及负责人当前权限；停用、降权、移除目标或更换凭据后，旧任务取消。正在网络传输的请求不能撤回；迟到响应不能覆盖已取消状态。

消息仅包含固定任务标签、状态、时间与事件编号，不含业务结果、数据库连接、内部异常或机器人凭据。系统创建的任务告警端点与普通模型 Webhook 隔离，无法通过普通端点管理界面变更用途。站内消息、告警状态与持久外发意图原子保存，意图写入失败会回滚本次状态变化；入队使用独立保存点，错误不回滚已保存的站内消息。命令以 `external_errors`、固定错误计数及非零状态提示；后续调度自动补偿到期意图，无需再出现新故障或恢复事件，也不重复站内消息。默认最多尝试 12 次、24 小时内有效，同一目标保持故障与恢复的入队顺序。显式 `--retry-external` 仅重试仍有授权且未过期的失败意图，不恢复已取消事件。策略、退避及诊断见 [入队补偿指南](p1-admission-and-contracts.md)。已入队消息的网络失败由原投递命令处理。

任务自监控可能形成后续告警：例如 Webhook 投递失败会被下一次任务评估观测；冷却仍限制提醒频率。真实群接收需按宿主部署另行联调，本批未向外部群发消息。

## 读取诊断指标

在「后台任务运行诊断」点击刷新，或读取原只读接口：

```text
GET <挂载前缀>/api/task-diagnostics/?database=default
```

权限仍限有效超级管理员；Session 与原中间件保持不变。新增两部分：

- `runtime_metrics`：公开数据读取成功、拒绝、限流与故障次数，取票状态、通知就绪、临时故障、续期、配置刷新、撤权与断开计数；取数平均耗时与直方图 P95 上界。
- `alert_deliveries`：任务告警投递的状态总数与最近 10 次记录；新增 `admission` 区分待入队、重试、已入队、取消和失败。仅显示机器人引用、固定错误码和尝试次数，已入队不表示已送达。

服务端指标覆盖当前分钟及之前 5 个分钟桶，计数键在 420 秒内过期。使用共享缓存原子 add/incr，不存用户、IP、页面、模型、参数、令牌或业务值。缓存失效不阻断取数、通知或鉴权；诊断返回不可用提示。指标为尽力观测，缓存淘汰和并发读取可能产生不完整桶；P95 是分桶上界，不是精确分位数，也不代表生产 SLO。服务端断开次数不等同当前活跃连接数，续期次数不等同客户端成功重连次数。

同页还显示当前浏览器会话的读取、重试、429、超时、单队列最高并发与排队峰值、连接尝试及就绪计数。这些固定大小的本地计数不上传服务器，不等于全站总量；刷新浏览器重置，不包含其他窗口。

`ordloom_check --probe` 也会检查公开通知启用时的事件通道；随机临时组收发不需要业务授权、不产生公开票据，不能代替实际代理、同源、CSRF、授权与 WebSocket 完整联调。
