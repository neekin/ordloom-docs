# Ordloom 1.2.0：CRM 与九应用生态

1.2.0 新增 CRM 客户关系 MVP，并首次分发到期提醒、工单服务台、资产台账、活动报名四个已开发应用，业务子应用合计九个。核心沿用 Python 3.9+/Django 4.2+ 与 SDK v1，不新增核心迁移。新增子应用各为 0.1.0，各自执行初始迁移；CMS、会员、商城、微信保留已发布的 0.1.0 原始产物。

## 安装与升级

```bash
pip install --upgrade ordloom==1.2.0
pip install ordloom-crm==0.1.0
# 按需安装本轮其他新包
pip install ordloom-reminders==0.1.0 ordloom-tickets==0.1.0 ordloom-assets==0.1.0
pip install ordloom-events==0.1.0
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check
```

新增应用仍须在宿主注册对应 `<模块>.apps.ExtensionConfig`。CRM、提醒、工单、资产没有公开 URL；活动报名显式挂载 `ordloom_events.urls`，并依赖会员。CRM 按客户负责人隔离，客户转交同时改变其联系人、线索与跟进记录范围；线索阶段及跟进任务见 [CRM 指南](../guides/crm.md)。其他新应用见 [运营子应用](../guides/operations-apps.md)与[活动报名](../guides/events.md)。

## 发行范围与验证

- 九个应用均包含后台概览和任务；八个应用提供静态搭建入口组件，会员无搭建组件。静态卡片不代表公开业务取数。
- CRM 提供客户、联系人、线索与只追加跟进记录，阶段校验、非负精确金额、到期提醒去重、当前权限与负责人复核。
- 源码组合与邮箱/UUID 账号、PostgreSQL、真实 wheel/sdist 独立/组合安装、迁移、静态与任务检查纳入发行门禁。
- 构建时复用已发布版本的原始 PyPI 文件；逐文件检查公开哈希，再与当前源码/README/依赖校验。原版本源码变化或产物冲突会拒绝发布。
- 保留核心/前端/共享缓存/第三方契约与至少 30 分钟同一候选双实例持续运行检查，通过后发布原始候选并复核 PyPI 哈希。

发行结果以 GitHub Release、PyPI 公开文件及本轮验收记录为准。真实宿主调度、业务容量与外部平台仍按部署验证；支付、CRM 团队共享与自动营销不在本次范围。
