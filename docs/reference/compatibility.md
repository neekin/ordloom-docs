## 已验证范围

2.0.0 统一命名后，在 Django 5.2、GraphQL/Channels 上完整发现 913 项后端检查，通过 911、跳过 PostgreSQL 专用并发 2 项；前端 159 项单元与 59 项 DOM 通过。
Python 3.9 / Django 4.2 核心与 Django 6 邮箱/UUID 账号专项各发现 45 项、通过 44、按可选运行时跳过 1；新名称 wheel 的核心与 GraphQL 扩展隔离安装也已检查迁移、静态资源和实际管理路由。
新功能另有 15 项真实浏览器和 7 项 Redis 跨进程功能检查；浏览器移动视口模拟、临时数据库及缓存检查不代表实际生产容量或真机验收。

这不等同于所有第三方 Admin 插件、任意自定义 HTML 控件都能自动转为同样的 React 组件。特殊控件可按[组件扩展契约](../development/extension.md)接入。

## 集成边界

- 模块直达使用页面 hash；原生 Admin 对象编辑 URL 还不是一对一的 SPA 编辑弹窗映射。
- 地图提供经纬度选择，不提供 POI 搜索。
- Markdown 保存原文，支持 GFM，不执行脚本或图表代码。
- 业务凭据控件提供只写交互，不自动加密数据库。
- 文件上传独立于数据库事务，取消编辑不会自动清除已上传文件。
- 审计与统计使用当前业务可见范围；归档/硬删除对象的特殊审计需求由项目钩子补充。
- 核心资源随包提供，但外部图片、视频和默认地图瓦片仍依赖对应服务。

## 升级检查

先在测试环境升级依赖，执行必要迁移与静态资源收集，验证业务表单、权限及文件存储。改变自定义用户模型本身属于 Django 项目迁移，不应仅因更换界面就直接修改已有用户表结构。

2.0.0 使用 `ordloom` 应用自己的迁移记录与表；限速默认开启，任务诊断默认关闭。共享缓存、可信来源地址与宿主任务调度仍需按部署配置。
