# 当前能力与后续方向

当前已发布 **Ordloom 1.1.0** 和四个独立子应用 **0.1.0**。核心提供 SDK v1、页面/数据/问卷增强和告警入队补偿；子应用最低要求核心 1.1.0。安装、升级和能力边界见 [1.1.0 发布说明](../releases/1.1.0.md)。

[正式发行](https://github.com/neekin/simpleui-antd/releases/tag/ordloom-v1.1.0) 已完成，五个包的 GitHub/PyPI SHA256 与源码核对一致；Django 4.2/5.2/6.0 手动门禁、1801 秒双实例持续运行及 5917 次 HTTP 读取通过。公开 PyPI 默认安装选中 Django 6.1.3，补充 1491 项回归（1479 通过、12 项环境条件跳过），并验证迁移、GraphQL 和四套行业配方。以下后续业务增强继续独立排期。

## 1.2.0 CRM 与运营应用

CRM 已落地客户、联系人、线索与只追加跟进记录，按客户负责人隔离，包含阶段校验、精确金额概览、到期跟进去重提醒和静态卡片。到期提醒、工单、资产、活动报名一并进入首次发行，合计九个子应用。核心 1.2.0 无新增迁移；全部门禁与公开产物核验后记录发布状态，见 [1.2.0](../releases/1.2.0.md)和 [CRM](../guides/crm.md)。

CRM 首版不含公海、团队共享、自动分配、报价合同或支付。下一独立应用为预约，再到审批；P2 业务闭环顺序保持。

## P1 已完成与发行保障

- P1-1：外发意图与站内消息/告警状态原子保存；共享缓存租约、行锁与事件唯一、有界退避/期限、逐目标独立及入队排序。撤权或原目标变化取消旧补偿，不使用新凭据追发旧事件。
- P1-2：实际 wheel/sdist ESM 语法/activate/注册与宿主 React/Ant Design 渲染；逐应用运行数与覆盖。旧包创建记录，新包同库迁移，保留业务数据、已保存组件及权限；支持 Email/UUID User 和命名空间，破坏性反例拒绝。
- P1-3 已发行：核心与四子包依赖下限、文档/目录/生成器及逐包产物门禁统一；已直接安装本批原始产物，完成新 ≥30 分钟双实例持续运行，核对 PyPI 全部文件 SHA256 后公开 GitHub Release。

`ordloom_check_apps` 仍只检查声明，`--baseline` 不代表有数据升级；前端契约使用 jsdom。完整范围见 [P1 指南](../guides/p1-admission-and-contracts.md) 与源码仓库发行记录，不能替代生产负载、目标浏览器/真机或真实平台验收。

## 下一步优先级

| 优先级 | 开发方向 | 范围 |
| --- | --- | --- |
| P2-1 | 会员身份恢复与微信撤权 | 先验证联系方式和真实平台事件，再实现找回/注销/个人数据流程及来源会话撤销；历史未验证邮箱不直接用于授权 |
| P2-2 | CMS 历史恢复与业务数据组件 | 先补全文比较/恢复草稿，再提供受控文章列表、商品卡片；公开查询复核发布快照、会员与当前权限 |
| P2-3 | Payments 与商城支付闭环 | 单商户/CNY/一个实际渠道，核价、回调验签幂等、主动查询、退款对账和库存补偿；支付包尚未实现 |
| P2-4 | 微信业务消息 | 从一个已提交业务事件开始，定义消费、重放/重试、订阅授权、留存和平台验收，再扩展菜单/素材 |
| P3 | 行业应用与生态分发 | CRM、工单、提醒、资产、活动已落地；后续预约 → 审批，营销待会员/交易闭环稳定后推进；出现真实第三方需求后维护来源/签名和更广兼容矩阵 |

高级数据按具体模型与规模推进：受控公式/同比环比、多值关联或多模型、第三方 HTTP 输入、数据库与全文索引适配。每项先定义权限、类型、精度、查询预算与部署验收，不开放任意 ORM 路径或在线代码。

共享缓存、ASGI 代理、任务调度、组织/租户映射、真实机器人/微信账号、HTTPS、目标大屏长期轮播及真机由宿主验证。云函数与在线自定义代码继续仅调研，尚未开发。
