刷新、变更通知与只读数据服务 ​

组件可以独立选择请求或通知。模型事件只通知失效，业务值重新查询；外部服务凭据只授予其明确的数据范围。

变更订阅（可选事件扩展） ​

在 settings.py 配置 ORDLOOM_EVENTS = {'enabled': True} 并安装 channels/daphne 后可用; 未启用时全部接口与行为保持不变。

  • 事件总线:ordloom/graphql/events.py——已注册 GraphQL 模型的保存/删除在事务提交后 (transaction.on_commit)写入共享 Django cache 序号(多实例一致)并按 channels 组广播; 批量 update()/queryset.update 与原始 SQL 不产生事件。
  • WebSocket:宿主可将 ASGI_APPLICATION = 'ordloom.asgi.application'(或在自己的 ProtocolTypeRouter 中组合 ordloom.routing.websocket_router),路径 <挂载点>/ws/visual-events/。 连接即鉴权(staff)，连接、签名与转发消息复核当前模型/字段权限；权限撤销或停用账号即停止通知。 路由校验 Origin，兼容 /admin/ 等挂载点。业务重读继续执行完整权限检查。
  • GraphQL Subscription:启用事件扩展后 Schema 提供 visualEvents 订阅字段(graphql/subscriptions.py), 依赖宿主 channel layer。
  • 轮询兜底:GET /api/visual-events/signature/(staff)校验当前账号权限，返回获授权模型的缓存序号与聚合摘要； 前端在未配置 channels 时自动退化为签名轮询(15 秒,页面隐藏暂停)。
  • 自动刷新集成:/api/datasets/<id>/execute/、报表执行与公开授权数据响应均标注 model; 前端绑定组件收到所属模型事件后按与手动刷新相同的路径自动重读(含在途合并、切屏取消、迟到结果隔离)。
  • /api/config/ 增加公开的 events 能力标志(enabled/websocket),不含任何数据或权限信息。

同一数据库事务内对同一模型的多次保存/删除只生成一次提交后通知；回滚不会通知，发送失败不影响已提交业务操作。 信号按实际数据库连接注册提交回调。批量更新、批量创建、原始 SQL 与外部写库需要业务方显式接入变更通知。 客户端在 WebSocket 正常时通过签名心跳校验遗漏事件，断线时使用 HTTP 签名兜底；签名请求不堆积，退出时清理任务。

订阅与签名限流 ​

ORDLOOM_EVENTS 还支持以下选项，均为 1–100000 的整数：

python
ORDLOOM_EVENTS = {
    'enabled': True,
    'signature_per_minute': 120,      # 同账号 HTTP + WS 签名请求共用
    'subscriptions_per_minute': 30,  # 同账号 WS 连接 + GraphQL 订阅建立共用
    'messages_per_minute': 120,      # 同账号所有 WS 客户端消息共用
    'max_message_bytes': 4096,       # 单条 WS 文本消息的 UTF-8 字节数
}

计数复用 Django cache 的 add/incr 固定 60 秒窗口；多实例需共享 Redis。 超限的 HTTP 签名返回 429 与 Retry-After: 60，WS 关闭码 4429，GraphQL 返回 RATE_LIMITED 和 retryAfter: 60；客户端会退避重试。非法 JSON、非对象或未知命令关闭码为 4400，二进制消息为 1003，过大文本为 1009。限流不取消业务写入或已有合法订阅的变更通知。 握手前被拒的 WS 在浏览器中通常表现为 403/1006，客户端沿用指数退避；已建立连接收到 4429 则等待 60 秒。 这是请求及订阅建立频率限制，不是并发连接上限；ASGI/反向代理还需按容量设置连接和帧大小上限。

多实例 Redis 与 ASGI 部署 ​

安装宿主需要的运行时（核心安装仍不要求事件依赖）：

bash
pip install 'ordloom[graphql]' channels channels-redis daphne redis
python
import os

ORDLOOM_EVENTS = {'enabled': True}
CACHES = {'default': {
    'BACKEND': 'django.core.cache.backends.redis.RedisCache',
    'LOCATION': os.environ['ORDLOOM_CACHE_URL'],  # 例如 redis://127.0.0.1:6379/1
    'KEY_PREFIX': 'ordloom-production',
}}
CHANNEL_LAYERS = {'default': {
    'BACKEND': 'channels_redis.core.RedisChannelLayer',
    'CONFIG': {'hosts': [os.environ['ORDLOOM_EVENTS_REDIS_URL']], 'prefix': 'ordloom-production-events'},
}}
ASGI_APPLICATION = 'myproject.asgi.application'

宿主 myproject/asgi.py 先初始化 Django，再加载可选路由：

python
import os
from django.core.asgi import get_asgi_application

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'myproject.settings')
django_http = get_asgi_application()

from channels.routing import ProtocolTypeRouter
from ordloom.routing import websocket_router

application = ProtocolTypeRouter({'http': django_http, 'websocket': websocket_router})

启动 daphne -b 127.0.0.1 -p 8001 myproject.asgi:application；反向代理保留挂载点、Host、Upgrade 与 Connection。 例如部署在 /admin/ 时，将 /admin/ws/visual-events/ 代理到同一 ASGI 服务，并启用 WebSocket 升级。 各实例共享 cache 与 channel layer；内存后端只适合单进程开发，固定窗口计数的跨进程原子性依赖 Redis 等原生实现。 协议服务和 Redis 配置依据 Channels 部署文档， 来源域限制依据 Channels WebSocket 安全文档。

外部只读数据服务 ​

服务身份用于后端集成，不依赖浏览器登录 Cookie。先安装可选 GraphQL 扩展、配置模型字段白名单并应用迁移：

python
# settings.py；已有 ORDLOOM_GRAPHQL 配置保持不变
ORDLOOM_DATA_SERVICES = {
    'enabled': True,                  # 默认关闭；需要 GraphQL 运行时
    'allow_http': False,              # 仅隔离本机验收可设 True
    'max_services_per_user': 20,      # 1–100，包含已撤销身份，身份可编辑复用
    'requests_per_minute': 60,        # 1–10000，每个服务共享的固定窗口预算
    'auth_attempts_per_minute': 120,  # 1–10000，每个直连 IP 的总准入预算
    'max_lifetime_days': 365,         # 1–365，必须明确设置到期时间
    'permission_context': None,      # 可选宿主可信权限上下文工厂
}
bash
python manage.py migrate
python manage.py ordloom_check --json

启用后在右上角账号菜单进入「外部数据服务」。创建人管理自己的服务，超级管理员管理全部；关联账号固定为创建人，不能通过请求切换账号。 新建/轮换只返回一次 ordloom_<身份UUID>.<随机密钥>，数据库保存随机 256 位凭据的 SHA-256 摘要，列表、操作记录和后续详情不返回凭据或摘要。 完整凭据不写入组件、页面文档或浏览器持久存储。请在服务端密钥存储中保存；响应丢失时从列表找到身份后轮换，旧凭据随即失效。 服务可撤销或编辑后重新启用，必须设置未来的到期时间；已过期身份先编辑有效期，再轮换。轮换不自动启用已撤销身份。

授权范围与现有权限 ​

两类范围独立，可选择其中一种或同时配置：

  • model_fields：最多 20 个模型，每模型最多 100 个明确字段；授权模型必须在宿主 GraphQL 白名单中，并且当前账号可见。 外部 GraphQL 的输出、筛选、排序、聚合和 introspection 均使用此受限结构，不提供未授权模型或字段。 关联字段仅在目标模型主键也有明确授权、且目标对象和主键当前可见时返回授权 ID。
  • dataset_versions：最多 50 个 {"id":"12","version":1}；必须为创建人/超级管理员当前可管理的已发布版本。 授予该固定查询及其完整输出，仍检查所有输出、筛选、排序和聚合依赖的当前权限；不隐含模型直接查询授权，也不自动包含未来发布版本。 运行时可传定义允许的类型化参数及分页，不能替换查询定义、增加输出字段或提高保存的 limit。

每次请求从数据库重新读取凭据状态、有效期和关联账号。账号被删除、停用或失去 staff/superuser 资格后拒绝读取；模型/模块、QuerySet、软删除、对象及动态字段规则继续由原数据层执行。 超级管理员修改别人的身份时同时检查自己的范围与原创建人的权限；权限已经撤销时仍可停用服务。 权限按请求执行，已经返回的结果和正在执行的请求无法追溯撤回；不缓存业务结果或服务权限。last_used_at 最多每分钟更新一次，不作为逐次访问日志。 凭据独立于密码/TOTP，密码修改不会自动轮换服务凭据；需要停止集成时撤销该身份。

默认权限上下文为新构造的只读请求及空 Session，不继承外部 X-Workspace、查询参数、Cookie 或浏览器账号。 如果 ModelAdmin 依赖租户等宿主上下文，可配置受信任的 Python callable（或其 dotted path）：

python
from django.test import RequestFactory

def data_service_context(user, service):
    request = RequestFactory().get('/internal/data-service/')
    request.user = user
    # 从宿主数据库中的受信任账号/组织关系推导租户；不要使用外部请求的任意头。
    request.tenant = user.profile.tenant
    return request

工厂签名 (user, service) -> HttpRequest，应用强制使用刚从数据库读取的关联账号，工厂异常拒绝访问。 原 ORDLOOM_LOGIN_IP_ALLOWLIST 同样限制服务入口，只检查 REMOTE_ADDR；反向代理需自行正确设置连接来源。 生产入口要求 HTTPS，代理终止 TLS 时按宿主可信代理策略配置 SECURE_PROXY_SSL_HEADER；不会直接相信任意 X-Forwarded-Proto。 多实例应使用共享 Redis cache，令身份/IP 预算在实例间共享；不把基础频控描述为生产容量保证。

管理和外部读取 API ​

路径均相对于应用挂载点。管理接口继续要求 staff Session，写操作保留 CSRF；外部凭据不能登录或访问这些管理接口：

接口行为
GET/POST /api/data-services/按权限分页/创建，返回每页 20 条
GET /api/data-services/catalog/当前可授权字段目录与有效期上限
GET/PUT/DELETE /api/data-services/<id>/查看/编辑/撤销；写入提交当前 revision，冲突返回 409
POST /api/data-services/<id>/rotate/{"revision":1} 轮换凭据；旧凭据立即失效

创建/编辑字段为 name、enabled、带时区的 expires_at、model_fields 和 dataset_versions。 创建、修改、撤销及轮换与 Django 操作记录同事务提交，记录不含密钥、查询参数或业务结果。

下列入口只使用 Authorization: Bearer …，不接受 Session 兜底或 URL 参数凭据，读取响应均为 no-store，不设置登录 Cookie：

接口行为
GET /api/data/catalog/当前受限模型/字段目录及已授权固定版本列表
POST /api/data/graphql/受限 GraphQL 查询；没有写入、订阅和管理操作
POST /api/data/datasets/<id>/versions/<number>/{"params":{},"offset":0,"limit":10} 执行固定版本，参数可省略

以服务端环境变量读取凭据，例如应用挂载于 /admin/：

python
import json, os
from urllib.request import Request, urlopen

request = Request(
    'https://admin.example.com/admin/api/data/datasets/12/versions/1/',
    data=json.dumps({'params': {}, 'limit': 10}).encode(),
    headers={'Authorization': 'Bearer ' + os.environ['ORDLOOM_DATA_TOKEN'],
             'Content-Type': 'application/json'}, method='POST')
with urlopen(request, timeout=15) as response:
    result = json.load(response)

无效/过期/撤销凭据返回 401 和 WWW-Authenticate: Bearer；权限不足返回 403，频控返回 429 与 Retry-After: 60。 GraphQL 查询错误保留 GraphQL errors 结构，错误消息和服务端默认错误日志不会输出宿主权限异常、请求字面量或密钥。 外部请求最多 64 KiB，继续使用数据层的查询深度、token 数、操作数、分页、分组及动态权限扫描上限。此入口不增加跨域放行策略。 Session 的 CSRF 策略与服务凭据认证分开处理，依据 Django CSRF 和 DRF 非 Session 认证说明；受限 schema 的可发现结构遵循 GraphQL introspection。

隔离验收：scripts/dev_fields.py --data-services --production --port=8660 启用本机 HTTP 测试，临时数据库使用合成业务数据。 在 frontend 运行 npm run test:data-services，覆盖可视化授权、真实无 Session 读取、字段限制、版本隔离、轮换撤销、修订冲突、跨账号与移动界面。
