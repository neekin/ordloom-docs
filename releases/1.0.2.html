Ordloom 1.0.2 稳定性更新 ​

本版完成公开通知故障恢复、多组件取数调度、手动发布门禁与持续运行验证三项 P1。原有模型、字段、组织及资源权限、数据集发布版本和共享缓存机制继续生效，公开通知仍默认关闭。

  • 临时缓存、数据库与通道异常不会永久撤销公开更新；重新领取票据并重新鉴权后恢复。真实撤权仍清空结果并停读，配置变化会重新加载公开页面与映射。
  • 数据集与嵌入报表共用最多 3 路读取；支持消费者取消、15 秒超时、最多 2 次临时重试、429/503 冷却、轮询错峰和公开页预算协调。手动、轮询、推送仍独立工作。
  • 手动 Release 先跑回归和跨进程服务检查，核对已提交的 30 分钟持续运行证据，再验证 wheel/sdist、迁移和静态清单，全部通过后发布同一批产物。普通提交不触发 Actions。
bash
pip install --upgrade ordloom==1.0.2
# 可选数据层
pip install --upgrade 'ordloom[graphql]==1.0.2'
python manage.py migrate
python manage.py collectstatic --noinput

本版没有新增数据库迁移；1.0.1 的 0027 及既有迁移仍保留。后端核心仍支持 Python 3.9+/Django 4.2+，可选数据层需要 Python 3.10+/Django 5.2+。已经启用通知的宿主无需新增配置，建议显式设置 Redis 连接与读取超时。

部署示例、调度额度、短断恢复与验证范围见 1.0.2 使用指南。30 分钟隔离运行属于有界验证，目标设备的 24 小时以上轮播、实际代理和业务负载仍需在部署环境验收。

本版双实例运行 1802 秒、完成 5916 次读取，最大并发 3、单页滚动 60 秒最多 100 次，撤权后队列与连接归零。原生轮播运行约 21 分钟、切换 80 次，无脚本错误。后端 965 项通过、2 项环境跳过；前端单元 173 项、DOM 71 项、PostgreSQL 90 项及发布门禁 8 个正反例通过，wheel/sdist 四种隔离安装和迁移验证完成。这些结果不作为生产环境 SLO。
